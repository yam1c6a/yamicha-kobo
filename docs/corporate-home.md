## デザインの基準

モックは `docs/design/atelier-reference-desktop.webp`、`atelier-reference-lower.webp`、`atelier-reference-mobile.webp` に保存している。これらは参照デザインであり、実装のスクリーンショットではない。

- 生成り `#F4F0E7`、墨色 `#302F29`、オリーブ `#45553E`、小さな桃色のアクセント。
- 見出しはNoto Serif JP、本文と操作部はNoto Sans JP。紙の質感と、窓辺の仕事机・ノート・植物のコラージュを使用する。
- 見出しは「いつもの仕事に、ちょうどいいAIを。」。PCではコラージュと説明を横に並べ、スマートフォンでは説明と相談ボタンを先に置く。
- サービスは「AI活用・業務自動化」「業務システムの開発」「既存システムの改修・保守」を罫線で区切る。装飾用の連番は置かない。
- 工房紹介、開発中のYAMIOS、仕事の進め方、FAQ、相談フォームまで一続きで読める構成。
- AWS・対応言語・データ連携の詳細は `#skills` にまとめる。`#cloud-aws` へ直接移動すると親の折りたたみも開く。

## 継続する実績と機能

実績の正本は `src/data/case-studies.js`。用途・目的、主な機能、設計・実装、システム構成を含む8件と既存の `#case-*` を維持する。現在のmainにある代表3件は、AIエージェント、既存システムの改修・保守、AI文書管理。改修・保守のリンクは実在する `#case-geospatial-versions` を開く。

守秘義務の注意書きと、税務上の最終判断を税理士が行う境界を表示する。顧客名、効果数値、口コミ、架空の実績は追加しない。

AI相談室は `#consult` の折りたたみから使う。既存の `/api/chat`、履歴、回数制限、入力内容の取り扱い説明、実績参照ロジックは維持する。YAMIOSへのリンクは既存の概要・連携案内 `/yamios/` に接続する。製品ページと各プライバシーページのデザインは変更しない。

## お問い合わせ

既存の窓口は `contact@yamicha.com`。フォームはメール本文の作成を補助する。

1. お名前、メールアドレス、ご相談内容を入力。会社名・屋号は任意。
2. 必須入力と空白だけの入力を検証し、ネイティブdialogで本文を確認。
3. メールアプリを開いて利用者自身が送信する。開かない場合は本文をコピーして同じ窓口へ送れる。

メールの配送処理・送信完了表示・サーバーへの入力保存は実装しない。画面にはメールアプリから送信することを明記する。AI相談室からの引き継ぎは利用者の入力だけを取り込み、長文は明示したうえで抜粋する。既入力の上書きは行わず、追加操作を提示する。4000字を超える場合は理由を知らせ、既入力と抜粋を保持する。

## 画像・アイコン

`public/images/atelier/` の4枚は選択デザインに合わせて生成した画像。コラージュは透過WebP、背景は紙のテクスチャ。製品画面や実績の実画面を装うものではない。

## 検証コマンド

```sh
npm ci
node --test tests/*.test.mjs
npm run build
node scripts/verify-home.mjs
```

生成HTMLについて、主見出しが1つ、サービス3件、対応技術、代表3件と全8件、守秘義務、同一ページ内アンカー、フォームのラベルとARIA参照、既存チャットのIDを検証する。

通常の開発はリポジトリのAGENTS.mdに従い `npx astro dev --background` で起動する。`npx astro dev status` / `logs` / `stop` で管理する。AIの実呼び出しをしない画面確認には `ATELIER_LOCAL_PREVIEW=1` を指定すると、Cloudflareのremote bindingsとローカルinspectorを無効にできる。この指定がない通常のビルド・本番動作は変更しない。

ブラウザーでは320 / 390 / 768 / 920 / 1440pxの表示、横はみ出し、モバイルメニュー、折りたたみ、フォーム・dialog・コピー、キーボードフォーカスを確認する。結果と未確認事項はルートの `design-qa.md` を参照する。ビルド成功を画面検証の代用にはしない。

`main`へのpushは本番公開につながるため、別ブランチとドラフトPRで確認する。本番反映は表示検証と承認の後に行う。
